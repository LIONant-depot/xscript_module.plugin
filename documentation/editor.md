# Script modules and the game DLL

A script module resource is only source files: its descriptor's `source_db` folder holds the `.h` and `.cpp` files. The
editor turns the modules a project references (`Project.config/Script.config.txt`) into the game DLL:

```
<project>/Cache/Script/CMakeLists.txt        generated by the editor from the referenced modules; never checked in
<project>/Cache/Script/Build/                the Visual Studio solution (Script.sln) and its intermediate files
<project>/Cache/Script/Loaded/               the copies of Game.dll that are actually loaded (Game_loaded_<n>.dll, Game.pdb)
<project>/Cache/Resources/Platforms/WINDOWS/Game.dll    the compiled resource
```

The editor regenerates the project when the module list changes and once when the project loads, and builds it when
`Game.dll` is older than what it is built from (the module sources, the generated project, or the two files in
`source/Runtime`). It never loads `Game.dll` itself but a numbered copy, so a rebuild never fights a file that is mapped.
Builds run in the background and a failed one leaves the loaded generation untouched.

## source/Runtime

What the generated project compiles in, and what module authors include:

| File | What it is |
|---|---|
| `xscript_registration.h` | `XSCRIPT_REGISTER_COMPONENT(type, category, priority)` and `XSCRIPT_REGISTER_SYSTEM(type)`: a module announces its components and systems through a self-registering list, so it is registered just by being compiled into the DLL |
| `xscript_game_entry.cpp` | the DLL's entry points (`XecsPlugin_RegisterComponents`, `XecsPlugin_RegisterSystems`, `XecsPlugin_Unregister`) and `XScript_GetComponentDisplayInfo`, which hands the editor each component's guid, name, category and priority |

A module includes `plugins/xscript_module.plugin/source/Runtime/xscript_registration.h`. The DLL links the xECSV2 import
library of the editor's own build, so it shares the editor's one component registry.

## Where the editor half is

The code that generates, builds and loads the project (and reloads the world around a new DLL) is still in the E29 example,
`extensions/game_module`. It is meant to move into `source/Editor` here.
